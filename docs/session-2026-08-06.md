## 1. רשימת המשתמשים במסך האדמין לא נטענה — `cf0ae07`

**התסמין.** מסך `/admin`, לשונית "משתמשים", נשאר ריק. הקונסולה חזרה על:

```
Access to fetch at '.../functions/v1/admin-manage-users'
from origin 'https://www.bzb-web.com' has been blocked by CORS policy:
The 'Access-Control-Allow-Origin' header has a value 'https://bzb-web.com'
that is not equal to the supplied origin.
```

**הסיבה.** `supabase/functions/_shared/auth.ts` הגדיר קבוע:

```ts
export const corsHeaders = {
  "Access-Control-Allow-Origin": ALLOWED_ORIGINS[0],  // "https://bzb-web.com"
  ...
};
```

כל שמונה הפונקציות ענו ל־preflight (`OPTIONS`) עם האובייקט הזה. מכיוון שהוא
מקובע ל־origin אחד, כל קורא אחר נחסם — כולל `www.bzb-web.com` וכולל תצוגות
מקדימות ב־`*.vercel.app`, למרות ששניהם כבר היו ב־`ALLOWED_ORIGINS`.

הפונקציה `corsOrigin(req)` כן פתרה את זה נכון, אבל כמעט לא נקראה: `json()`
השתמשה בה רק כשקיבלה `Request` מפורש, ו־89 מתוך קריאות ה־`json()` בקוד לא
העבירו אחד.

**התיקון.** `withCors()` שומר את ה־`Request` ב־`AsyncLocalStorage`, כך ש־`json()`
קורא אותו בלי שצריך לשרשר פרמטר ל־89 מקומות:

```ts
const requestContext = new AsyncLocalStorage<Request>();

export function withCors(handler: (req: Request) => Response | Promise<Response>) {
  return (req: Request) =>
    requestContext.run(req, async () => {
      if (req.method === "OPTIONS") {
        return new Response("ok", { headers: corsHeadersFor(req) });
      }
      return await handler(req);
    });
}
```

נוסף גם `Vary: Origin`, שמונע מ־proxy להגיש headers של origin אחד לקורא ממקור אחר.

**למה `AsyncLocalStorage` ולא שרשור מפורש.** נשקלו שלוש דרכים:

| דרך | שיקול |
|---|---|
| לשרשר `req` ל־89 קריאות | נכון וטריוויאלי, אבל 89 עריכות ב־`json(...)` עם סוגריים מקוננים הן משטח טעויות גדול |
| `Access-Control-Allow-Origin: *` | היה עובד (האימות דרך header ולא cookies), אבל מוחק allowlist שהקוד בבירור התכוון אליו |
| `AsyncLocalStorage` | עריכה אחת מרכזית |

**הסיכון שנלקח.** `AsyncLocalStorage` הוא global מרומז — קשה יותר לעקוב אחריו
מפרמטר מפורש, ואם Supabase יחליף runtime הוא עלול להישבר בשקט. כמיתון, `json()`
נופל חזרה ל־`ALLOWED_ORIGINS[0]` כשה־store ריק, כלומר במקרה הגרוע חוזרים
להתנהגות הקודמת ולא לקריסה.

**אימות מול הפרודקשן** (לא הסקה — `curl` בפועל):

- preflight מ־`www.bzb-web.com` → `https://www.bzb-web.com` — בכל 8 הפונקציות
- POST אמיתי מ־`www` → `{"error":"unauthorized"}` עם ACAO של `www`. ההבחנה
  קריטית: 401 של ה־gateway מגיע עם `sb-error-code` ו־ACAO `*` ולא היה מוכיח
  כלום, בעוד `{"error":"unauthorized"}` הוא הפלט של `errorResponse` בקוד עצמו —
  כלומר מסלול ה־`AsyncLocalStorage` רץ
- apex → apex
- origin לא מוכר → נפילה חזרה, בלי הדהוד

**מה לא נבדק.** preflight נבדק על כל 8; POST אמיתי נבדק רק על
`admin-manage-users`. השאר עוברות באותו `withCors`, כך שההיגיון זהה — אבל זו
הסקה, לא מדידה.

**נוקה בדרך.** `admin-reset-password` החזיקה `json()` מקומי שכפל את המשותף; הוסר
לטובת הייבוא.

## 5. מסך האדמין הבהב בלולאה אינסופית

**התסמין.** כרטיסי "תמונת מצב" הציגו ערכים (18 משתמשים, 10 מטלות), חזרו לשלד,
והתמלאו שוב — ברצף אינסופי.

**הסיבה.** תלות מחזורית בין `useCallback` ל־`useEffect`:

```ts
const loadActivity = useCallback(async () => {
  const missingIds = ... .filter((id) => !profilesById[id]);
  if (missingIds.length > 0) setProfilesById(...);   // ← כותב
}, [profilesById]);                                   // ← וגם תלוי

useEffect(() => {
  if (isAdmin) { void loadActivity(); void loadStats(); ... }
}, [isAdmin, loadActivity, loadDuplicatePhones]);
```

`loadActivity` קורא את `profilesById` וגם כותב אליו. הכתיבה יוצרת זהות חדשה
לאובייקט, ולכן זהות חדשה ל־callback, ולכן ה־effect רץ שוב ומפעיל את ששת
הטוענים מחדש — כולל `loadStats`, שמעלה `statsLoading` ל־`true` ומחזיר את השלד.
זה ההבהוב.

**התיקון.** קריאת המטמון דרך `useRef`, כך שה־callback נשאר יציב:

```ts
const profilesByIdRef = useRef(profilesById);
useEffect(() => { profilesByIdRef.current = profilesById; }, [profilesById]);
// ובתוך loadActivity: !profilesByIdRef.current[id]  ·  deps: []
```

## 6. שתי אזהרות קונסולה

### תוקן — `aria-hidden` על מגירת הניווט

```
Blocked aria-hidden on an element because its descendant retained focus.
```

מגירת הניווט ב־`MobileNav.tsx` נשארת mounted כדי שתוכל להחליק, ולכן צריכה
להיסגר בפני טכנולוגיה מסייעת כשהיא מחוץ למסך. היא קיבלה גם `inert` וגם
`aria-hidden={!open}`.

`inert` לבדו כבר עושה את שתי העבודות: מסיר את התת־עץ מעץ הנגישות **וגם** מסרב
לפוקוס בתוכו. הצמד יצר תחרות — קישור במגירה יכול היה עדיין להחזיק פוקוס בפריים
שבו `aria-hidden` נכנס, וזה בדיוק מה שהדפדפן מדווח עליו. `aria-hidden` הוסר.

### לא תוקן ביודעין — `google.maps.Marker`

```
As of February 21st, 2024, google.maps.Marker is deprecated.
Please use google.maps.marker.AdvancedMarkerElement instead.
```

חמישה שימושים בשלושה קבצים: `MapView.tsx`, `GoogleMapPicker.tsx`,
`TaskLocationMap.tsx`.

זו לא החלפת שם — `AdvancedMarkerElement` דורש **Map ID** שמוגדר ב־Google Cloud
Console, טעינה מפורשת של ספריית `marker`, ו־API שונה לאייקונים ולתוכן. כלומר
שינוי קוד בשלושה קבצים ועוד תלות בהגדרת ענן.

מנגד, ההודעה עצמה קובעת ש־`Marker` **אינו** מיועד להפסקה, שהוא ימשיך לקבל
תיקונים לרגרסיות משמעותיות, ושתינתן התראה של 12 חודשים לפחות. אין כאן שבירה
צפויה. הוחלט להשאיר ולתעד, ולא לגרור מיגרציה עם תלות בהגדרת ענן לתוך סשן שעסק
בתיקוני CORS ו־build.

**מה יידרש כשכן נעשה את זה:** ליצור Map ID, להוסיף אותו לאתחול המפה, לטעון את
`marker` ב־loader, ולהמיר את חמשת מופעי ה־`new google.maps.Marker({...})`.

## נספח: למה `verify_jwt = false` אינו פרצה כאן

ארבע פונקציות מוגדרות `verify_jwt = false` ב־`config.toml`. ההגדרה מכבה את אימות
ה־JWT **בשער (gateway) של Supabase בלבד** — היא לא הופכת את הפונקציה לפתוחה.

`verify_jwt = true` אינו אפשרות עבורן, מפני שאף אחת מהן לא נקראת מדפדפן ולכן
אין לקורא JWT של משתמש כלל: `send-auth-email` נקראת מ־Supabase Auth,
והשלוש האחרות מ־`pg_net` דרך טריגר במסד או מ־cron. אילו השער היה דורש JWT, כל
קריאה לגיטימית הייתה נחסמת.

השאלה הנכונה היא לא אם השער מאמת, אלא אם הפונקציה מאמתת בעצמה. כל אחת מהן כן:

| פונקציה | מנגנון האימות |
|---|---|
| `send-auth-email` | חתימת Standard Webhooks מול `SEND_EMAIL_HOOK_SECRET` |
| `notify-dispatch` | סוד משותף בכותרת `x-notify-secret` |
| `send-parent-digest` | אותו סוד |
| `send-quiet-digest` | אותו סוד |

אומת בקריאה חיה לכל אחת, בלי אישור:

```
notify-dispatch        HTTP 401  {"error":"unauthorized"}
send-parent-digest     HTTP 401  {"error":"unauthorized"}
send-quiet-digest      HTTP 401  {"error":"unauthorized"}
send-auth-email        HTTP 401  {"error":{"message":"invalid_signature"}}
```

כל שאר הפונקציות — אלה שכן נקראות מהדפדפן — מוגדרות `verify_jwt = true`,
ו־`architecture-invariants.test.ts` אוכף זאת כדי ששינוי קונפיגורציה עתידי לא יהפוך
endpoint של משתמש לציבורי בשקט.

### מה כן ראוי לתשומת לב

**השוואת הסוד אינה constant-time.** שלוש הפונקציות משוות עם `!==`:

```ts
if (!expectedSecret || req.headers.get("x-notify-secret") !== expectedSecret) {
```

תיאורטית זה חושף ערוץ צדדי תזמוני. מעל HTTP, עם רעש רשת, ניצול מעשי קשה מאוד,
ולכן זה לא תוקן בסשן הזה — אבל זו החלטה מודעת ולא היעדר מודעות. מעבר ל־
`timingSafeEqual` הוא שיפור זול אם רוצים לסגור גם את זה.

**שלוש פונקציות חולקות סוד יחיד** (`NOTIFY_DISPATCH_SECRET`). דליפה של אחת חושפת
את שלושתן.

**`send-auth-email` מחזיקה הגדרת CORS משלה** עם `*`, ולא עברה ל־`withCors`
בסעיף 1. זה מכוון: היא webhook שנקרא server-side, אין לה origin לאכוף, וחתימת
Standard Webhooks היא מה שמאמת אותה. התוצאה היא שתי הגדרות CORS בקוד — חוב מודע.
חשוב לזכור שהיא **לא** פונקציית בדיקה: היא מוציאה את כל מיילי ה־auth בפרודקשן
(`signup`, `recovery`, `magiclink`, `invite`, `email_change`, `reauthentication`),
ואם היא נופלת אף אחד לא נרשם ולא מאפס סיסמה.
