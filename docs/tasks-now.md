# Busy Bee – רשימת המשימות לעכשיו

מסמך עבודה פשוט: מה צריך לעשות, באיזה סדר, ומתי משימה נחשבת "סגורה".
המטרה של השלב הזה היא **לייצב** את המוצר הקיים – לא להוסיף פיצ'רים חדשים.

---

## סדר עדיפויות בגדול

| שלב | נושא | למה זה ראשון |
|-----|------|---------------|
| 1 | סביבה וקוד מסודרים | בלי בסיס יציב כל בדיקה מתבזבזת |
| 2 | מיפוי המסכים והזרימות | צריך לדעת מה קיים לפני שבודקים |
| 3 | בדיקת משתמש: הרשמה, התחברות, אזור אישי | זו הכניסה של כל לקוח למוצר |
| 4 | בדיקת מטלות: יצירה, רשימה, מפה, ביצוע | זה הלב של המוצר |
| 5 | בדיקת כפתורים וקישורים | תקלות קטנות שהורסות אמון |
| 6 | התאמה למובייל ולמחשב | רוב המשתמשים יגיעו מהטלפון |
| 7 | תיקון תקלות | אחרי שיודעים מה שבור |
| 8 | ניקוי וסידור קוד | כדי שאפשר יהיה להמשיך לפתח |

---

## שלב 1 – סביבה וקוד מסודרים

- [ ] לוודא שהפרויקט עולה מקומית בלי שגיאות (`npm run dev`, פורט 8080)
- [ ] לוודא שהבנייה לייצור עוברת (`npm run build`)
- [ ] לוודא שאין שגיאות טיפוסים (`npx tsc --noEmit`)
- [ ] לוודא שכל משתני הסביבה קיימים (Supabase, Google Maps) ושיש קובץ דוגמה `.env.example`
- [ ] לוודא שהקוד מסונכרן מול GitHub

**סטטוס:** החיבור ל‑GitHub כבר קיים – `github.com/Oriram1/busybee-chore-connect`.
מה שנשאר: לוודא שכל השינויים נדחפים באופן קבוע ושיש ענף `main` נקי.

**סגור כאשר:** הפרויקט רץ, נבנה, ונדחף ל‑GitHub בלי שגיאות.

## שלב 2 – מיפוי המסכים והזרימות

- [ ] לרשום את כל המסכים הקיימים ומה כל אחד אמור לעשות
- [ ] לרשום מי רואה כל מסך (אורח / מציע מטלות / מבצע מטלות / הורה / אדמין)
- [ ] לסמן מסכים שאינם בשימוש או כפולים

**המסכים הקיימים היום:**

| מסך | כתובת | מיועד ל |
|-----|--------|---------|
| דף נחיתה | `/` | כולם |
| כניסה / הרשמה | `/auth`, `/login`, `/register/:role` | אורחים |
| מטלות זמינות | `/tasks` | כולם |
| פרטי מטלה | `/task/:id` | כולם |
| יצירת מטלה | `/create-task` | מציע מטלות |
| המטלות שלי | `/my-tasks` | מציע מטלות |
| צ'אט | `/chat` | מציע ומבצע |
| פרופיל | `/profile` | מציע ומבצע |
| לוח הורים | `/parent` | הורה |
| מנויים | `/pricing` | כולם |
| ניהול | `/admin` | אדמין |
| תנאים ופרטיות | `/terms`, `/privacy` | כולם |

**סגור כאשר:** קיימת טבלה מעודכנת של כל המסכים וההרשאות שלהם.

## שלב 3 – בדיקת הרשמה, התחברות ואזור אישי

- [ ] הרשמה כמציע מטלות – עוברת מקצה לקצה
- [ ] הרשמה כמבצע מטלות – עוברת מקצה לקצה
- [ ] הרשמה כהורה – עוברת מקצה לקצה
- [ ] התחברות עם משתמש קיים
- [ ] שחזור / איפוס סיסמה
- [ ] יציאה מהמערכת מנקה את הנתונים ומחזירה לדף הבית
- [ ] כניסה לאזור אישי – הפרטים מוצגים נכון
- [ ] עריכת פרטים אישיים נשמרת ומופיעה אחרי רענון
- [ ] העלאת תמונת פרופיל עובדת
- [ ] הודעות שגיאה ברורות בעברית (אימייל תפוס, סיסמה שגויה, שדה חסר)

**סגור כאשר:** כל שלושת סוגי המשתמשים נרשמים, מתחברים, עורכים פרופיל ומתנתקים – בלי תקלות.

## שלב 4 – בדיקת מטלות: יצירה, הצגה, ביצוע

### יצירת מטלה
- [ ] כל שדות הטופס נשמרים נכון (כותרת, תיאור, קטגוריה, מחיר, תאריך, שעה, מספר עובדים)
- [ ] בחירת כתובת דרך המפה עובדת ונשמרת
- [ ] אי אפשר לשלוח טופס חסר – מופיעה הודעה ברורה
- [ ] אחרי יצירה המשתמש מועבר למקום הנכון והמטלה מופיעה ברשימה

### הצגת מטלות
- [ ] רשימת המטלות נטענת ומציגה נתונים נכונים
- [ ] סינון לפי קטגוריה עובד
- [ ] סינון לפי מרחק עובד
- [ ] תצוגת מפה מציגה את המטלות במיקום הנכון
- [ ] מעבר בין תצוגת רשימה למפה שומר על הסינון
- [ ] לחיצה על מטלה פותחת את מסך הפרטים המלא
- [ ] מצב ריק ("אין מטלות") מוצג יפה ולא כמסך שבור

### תהליך ביצוע המטלה
- [ ] מבצע יכול להגיש מועמדות למטלה
- [ ] מציע רואה את המועמדים ויכול לאשר או לדחות
- [ ] סטטוס המטלה מתעדכן בכל שלב (פתוחה → שובצה → בביצוע → הושלמה)
- [ ] צ'אט בין הצדדים נפתח ועובד
- [ ] סימון מטלה כהושלמה עובד ומעדכן את שני הצדדים
- [ ] מטלה שהושלמה יורדת מרשימת המטלות הזמינות

**סגור כאשר:** אפשר לעבור מסלול מלא – יצירת מטלה, שיבוץ, ביצוע וסגירה – בלי התערבות ידנית.

## שלב 5 – בדיקת כפתורים וקישורים

- [ ] כל כפתור במסך מבצע פעולה (אין כפתורים "מתים")
- [ ] כל קישור מוביל לכתובת הנכונה
- [ ] כפתור חזרה מחזיר למסך הקודם הנכון
- [ ] לחיצה על לוגו מחזירה לדף הבית
- [ ] קישורי תנאי שימוש ומדיניות פרטיות עובדים
- [ ] כתובת לא קיימת מציגה מסך 404 עם דרך לחזור
- [ ] משתמש בלי הרשאה מקבל הודעה ברורה ולא מסך ריק

**סגור כאשר:** נעשה מעבר על כל המסכים ולא נמצא כפתור או קישור שבור.

## שלב 6 – התאמה לטלפון ולמחשב

- [ ] בדיקה בטלפון (רוחב 375 ו‑390)
- [ ] בדיקה בטאבלט (רוחב 768)
- [ ] בדיקה במחשב (רוחב 1280 ומעלה)
- [ ] אין גלילה לצדדים באף מסך
- [ ] טקסטים לא נחתכים ולא נדחסים
- [ ] טפסים נוחים למילוי בטלפון
- [ ] המפה עובדת טוב במגע
- [ ] כיווניות עברית (RTL) נכונה בכל המסכים

**בוצע:** התפריט במובייל הוחלף לתפריט תחתון בסגנון אפליקציה
(`src/components/BottomNav.tsx`). התפריט הצדדי נשאר למסכי מחשב בלבד.

**סגור כאשר:** כל המסכים נראים תקין בשלושת גדלי המסך.
