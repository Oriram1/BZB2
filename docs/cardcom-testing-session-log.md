# תיעוד סשן: בדיקות סליקת Cardcom על מסוף בדיקה

תאריך: 11.10.2026. המסמך מסכם את כל מה שנעשה, מה נמצא, מה תוקן, ומה נשאר לפני המעבר ללייב.
הפרטים הסודיים (שמות API וסיסמאות) לא נכללים כאן. הם ב־Supabase secrets, ובפאנל של Cardcom.

## תקציר

- סליקת המנויים נבדקה מקצה לקצה על **מסוף הבדיקה 1000** מול Cardcom האמיתי, באתר החי.
- נבנתה אפשרות להחזיק **שני מסופים במקביל** (בדיקה ולייב), ו־`CARDCOM_MODE` בוחר ביניהם. כרגע `test`.
- נמצאו ותוקנו **ארבעה באגים אמיתיים** שרק מסוף אמיתי חשף (ראו להלן).
- בסוף הבדיקות `BILLING_ENABLED` כובה, כדי שמבקרים לא יוכלו לרכוש מנוי חינם על מסוף בדיקה.
- המעבר ללייב עוד לא בוצע. מסוף הלייב (`197542`) לא נגעו בו.

## המסוף ופרטי הגישה

- פרטי ה"מפתח" ששלחה נציגת Cardcom ב־30.8 **לא עבדו** (קוד 603).
- הפרטים הנכונים נמצאו בפאנל, תחת **`Definition/APIKey.aspx`** ("ניהול מפתחות API לממשקים"): מפתח בשם "D7 api key", מורשה למסוף 1000.
- התחברות לפאנל נעשית ע"י המשתמש בלבד. סשן הפאנל פג אחרי זמן קצר.
- ה־secrets ב־Supabase:

| Secret | תפקיד |
|---|---|
| `CARDCOM_MODE` | `live` = לייב, כל ערך אחר = בדיקה (ברירת מחדל) |
| `CARDCOM_TEST_TERMINAL` / `_API_NAME` / `_API_PASSWORD` | מסוף בדיקה (1000) |
| `CARDCOM_TERMINAL` / `_API_NAME` / `_API_PASSWORD` | מסוף לייב (נשארו כפי שהיו) |
| `BILLING_ENABLED` | מתג ראשי. **כרגע `false`** (כובה אחרי הבדיקות, עד שמסיימים). להפעלה לבדיקה: `supabase secrets set BILLING_ENABLED=true` |
| `CARDCOM_ISSUE_DOCUMENTS` | חשבוניות, כרגע `false` |

## באגים שנמצאו ותוקנו

1. **מפתח חידוש ארוך מדי.** Cardcom דחה `ExternalUniqTranId` של 58 תווים (`UniqAsmachta Maxlen is 50`). נקצר ל־47. ה־mock אוכף עכשיו את אותה מגבלה.
2. **`notify-dispatch` ישן בפרודקשן.** נפרס ב־9.8, לפני שנוספו אירועי חיוב, ולכן מיילים ו־push של חיוב לא נשלחו כלל. נפרס מחדש, ואומת במייל אמיתי.
3. **חיוב כפול על רכישה ראשונה לא זוהה.** שני דפי תשלום פתוחים שנוסו לשלם גרמו לחיוב כפול בלי סימון ובלי אזהרה. עכשיו הזמנה `initial` שמשולמת כשהמנוי כבר `active` מסומנת `period_already_paid`, ולא מקבלת התראת הצלחה. אומת מקומית ונפרס (מיגרציה `20261011161500`).
4. **זיכוי של חיוב כפול ביטל את המנוי התקין.** `billing-refund` מדלג עכשיו על ביטול המנוי כשההזמנה מסומנת `period_already_paid`. אומת בפרודקשן.

עוד: ב־Vault בפרודקשן חסר `billing_renew_url`, ולכן ה־cron השעתי לא עשה כלום. נוסף.

## מה עדיין לא נבדק

- **חשבוניות** (`Document`): דורש מודול חשבוניות במסוף. `CARDCOM_ISSUE_DOCUMENTS=false`.
- **כרטיס שנדחה בדף Cardcom**: לא היה כרטיס כזה במסוף הבדיקה. הכשל נבדק עם כרטיס שפג תוקף.
- **מעבר ל־`CARDCOM_MODE=live`**.

## לפני המעבר ללייב

1. לאמת שוב חיוב כפול אחרי התיקון, ולוודא שהמייל השני לא נשלח.
2. לברר מול Cardcom אם מודול חשבוניות פעיל, ואז להפעיל `CARDCOM_ISSUE_DOCUMENTS=true`.
3. לנקות מנויי בדיקה: הטוקנים שלהם שייכים למסוף 1000 ולא ישרדו מעבר. לבטל או לאפס אותם.
4. להחזיר את התפקיד של `itayk93@gmail.com` מ־`tasker` ל־`bee` (אם רוצים), ולוודא ש־`admin` נשאר.
5. להחליט על שאלות הלקוח הפתוחות (`docs/cardcom-client-questions.md`): עמלת 3 ₪ למשימה בדף התמחור, ביטוח מטלות, ומה נחשב "שימוש" ב־14 ימים.
6. לעבור ללייב: `supabase secrets set CARDCOM_MODE=live`. חשוב: `BILLING_ENABLED=true` על מסוף בדיקה אומר שכל מבקר יכול לקנות מנוי חינם, ולכן אין להשאיר מצב כזה בפרודקשן לאורך זמן.

## הערות תפעוליות

- **Cloudflare:** דף התשלום של Cardcom מכיל בדיקת בוט. בדפדפן אוטומטי היא נכשלת. התשלום צריך להתבצע בדפדפן הרגיל של המשתמש.
- **תפקידים:** המערכת מאפשרת תפקיד אחד שאינו `admin` למשתמש (`one_role_per_user`). רק `tasker` יכול לרכוש מנוי.
- **Supabase CLI:** הטוקן שב־`.env.supabase.local` פג. ה־CLI עובד עם ההתחברות השמורה שלו (`env -u SUPABASE_ACCESS_TOKEN supabase …`).
- **סביבה מקומית:** פורט 8080 תפוס אצל המשתמש ע"י Docker, ולכן שרת הפיתוח המקומי רץ על 8090.
- **Vercel:** כל משתני `VITE_*` נמצאים שם. מפתחות Cardcom שייכים ל־Supabase בלבד.
